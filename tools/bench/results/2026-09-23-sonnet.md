## Isolation

Every one of the 80 cells was checked against its own transcript: no hook fired that its arm does not declare, no plugin skill was offered, and each system prompt held its own arm’s text and no other arm’s.

## Limitations

- n=2 per task and arm. Three agent sessions on one ticket differ by more than most of the gaps in these tables, which is why every number is a median with its interquartile range beside it and why a gap smaller than that spread is not a result.
- One model (sonnet) and one fixture (alan2207/bulletproof-react (apps/react-vite), a TypeScript React app). Nothing here transfers to another model or to a Python or Go repo without being run again.
- One ticket per session, started cold. TinyCorp runs long-lived Employees that carry a conversation across many turns, where the system prompt is paid once and cached — so an arm that adds text is priced here at its worst case, and an arm that changes behaviour per turn at its least.
- The terse voice governs DMs between Employees, and a bench session writes no DM. This measures what carrying the rule costs on a coding task, not what it saves on the messages it is about.
- The ponytail arms prepend its `SKILL.md` with `--append-system-prompt`. The skill really ships as a plugin activated by a `SessionStart` hook; ponytail’s own README says pasting the text is an approximation of its `full` level.
- RTK can only filter what goes through Bash, and a Claude Code session does most of its reading through Read, Grep and Glob, which no hook rewrites. The `rtk gain` table below is therefore a number about a slice of the session, not about the session.
- Not measured: whether the feature asked for was actually built, and whether it was built well. The fixture’s own suite is a regression guard — it catches a change that broke the repo — and it passes for a session that wrote nothing at all, so read `lines +` beside it, not instead of it.
- Not measured: quality, safety, or the review rounds a worse diff would cost downstream. An arm that spends 20% fewer tokens and needs a second attempt has saved nothing.
- Dependencies are installed once and every workspace links to that one tree, so no cell pays for `npm install`. Each cell checks the tree is unchanged afterwards and says so if it is not.
- Every cell’s isolation was checked against its own transcript and held.
